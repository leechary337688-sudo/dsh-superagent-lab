## 2. 模块职责与依赖

| 模块 | 职责 | 可以依赖 | 绝对不可以 |
|---|---|---|---|
| `core/` | 与游戏无关的基础设施 | 无（只有自身） | 任何业务/第三方/DOM |
| `content/` | 定义数据类型、加载 JSON、校验、地图解析 | `core/` 类型、`content/` JSON | `sim/`、渲染、UI |
| `sim/` | 规则与状态：经济/商店/合成/摆放/回合/战斗接口 | `core/`、`content/` **类型** | DOM、Pixi、Preact、`Math.random`、墙钟 |
| `app/` | 组装 sim + 内容，暴露会话与意图 | 下三层 | 渲染/UI 具体实现（只做回调） |
| `render/` | 把状态画成棋盘 | `core/`、`sim/`、`content/`、`pixi.js` | 修改状态、读 UI |
| `ui/` | 界面与交互 | 下三层、`preact` | 直接改状态（必须走 session） |
| `main.ts` | 入口装配 | 任意模块 | 放业务逻辑 |

**核心不变量：状态只能由 `sim/` 里的 action 产生；`app/session.ts` 是唯一提交点；
`render/` 和 `ui/` 只读。** 这条规则保证了「画面 = 状态」，联机/回放/测试都不会被 UI 干扰。

## 3. 命名与代码风格

| 类型 | 约定 | 例 |
|---|---|---|
| 代码标识符/文件名 | 英文，camelCase / PascalCase | `createRunState`、`ShopPanel.tsx` |
| 面向玩家的文字 | 简体中文，集中放 `ui/labels.ts` 或组件里 | 「调度中心」「休整期」 |
| 内容 id | kebab-case 或 snake_case 均可，**稳定不变** | `op_a`、`demo-board` |
| 内容文件名 | 建议与 id 一致 | `content/operators/amiya.json` 里 `"id": "amiya"` |
| 测试 | `<模块>.test.ts` | `tests/sim/shop.test.ts` |
| 文档 | 中文 + 数字前缀 | `docs/04-数据模型与Schema.md` |
| 时间 | 战斗内用整数 tick（30 tick = 1 秒） | `intervalTicks` |

- TypeScript 开启 `strict`、`noUncheckedIndexedAccess`、`noUnusedLocals`；数组下标访问必须处理 `undefined`；
- `import type` 导入纯类型（`verbatimModuleSyntax` 已开启）；
- 不引入 ESLint/Prettier（现阶段用 `tsc` + `check-layers` 兜底；要加请单独提 PR，避免和骨架混在一起）。

## 4. 常用命令

| 命令 | 作用 |
|---|---|
| `npm run dev` | 开发服务器（http://localhost:5173） |
| `npm run build` | 生产构建 → `dist/` |
| `npm run preview` | 预览构建产物 |
| `npm run typecheck` | `tsc --noEmit` |
| `npm test` / `npm run test:watch` | Vitest（含真实内容校验） |

## 5. 怎么加东西（常见任务）

### 加一个干员

1. 新建 `content/operators/<id>.json`，字段见 [04-数据模型](04-数据模型与Schema.md)；
2. 若引用了技能/盟约，先在 `content/skills/`、`content/synergies/` 建好；
3. `npm test` 会校验字段、引用和 id 唯一性；
4. 启动后商店会按稀有度自动抽到它（无需改代码）。

### 加一张地图

1. 新建 `content/maps/<id>.json`：`cols/rows/legend/layout`，`layout` 每行等宽；
2. 至少要有 1 个 `deployable`、1 个 `spawn`、1 个 `goal`；
3. 目前入口只加载**文件名排序后的第一张地图**（`demo-board`），多地图选择器是后续工作。

### 加一个盟约 / 一件装备 / 一波敌人

分别放 `content/synergies/`、`content/items/`、`content/waves/` 与 `content/enemies/`；
`operator.synergyIds` 引用盟约、`wave.rounds[].enemies[].enemyId` 引用敌人。
校验器会拦住悬空引用。

### 改规则数值

只改 `content/config/balance.json`（经济、商店概率、等级费用、整备区/上阵位、回合数），
不需要碰 `src/`。改完跑 `npm test`：`tests/content/load.test.ts` 会用真实数据重新校验。

### 加一个新模块目录（例如联机用的 `net/`）

1. 建目录；
2. 在 `tools/check-layers.mjs` 的 `MODULES` 里登记允许的依赖；
3. 在 [02-技术架构](02-技术架构.md) 的架构图里补一行。

## 6. 以后什么情况下拆包

现在单包 + 目录分层是有意为之：依赖少、工具链简单。出现下面任一情况再拆成 monorepo
（`apps/web`、`apps/server`、`packages/core`、`packages/sim`、`packages/content`）：

- 需要 Node 服务端复用 `sim/`（联机 M5，或做平衡模拟器/机器人）；
- 构建时间明显变长，或前端开始依赖 Node 包；
- 需要独立发布 `sim` 给其他客户端（例如桌面壳/移动壳）。

拆分时 `sim/` 已经零 DOM 依赖，迁移成本主要是 import 路径与 workspace 配置。
