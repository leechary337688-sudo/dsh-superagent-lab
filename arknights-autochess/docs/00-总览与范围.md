## 一句话目标

做一个**自走棋式运营 + 方舟式塔防战斗**的游戏：休整期招募/升星/凑盟约/摆阵，作战期自动战斗，
漏怪扣目标生命，14 回合打穿一局。

## 原始诉求（2026-11-13，对话原文意译）

> 我要做一个自走棋玩法的明日方舟游戏，类似云顶之弈和崩铁的货币战争，就在这个仓库里做。
> 地图部分参考卫戍协议，比如底部的放置人物的格子，还有角色，看看有没有开源的角色。
> 先想好怎么构建，在仓库里创建新文件夹，想好目录和组织架构，内容等我回来再动，
> 可以参考别人的游戏经验和 skill，和一些已开发的相关项目，就是先搭框架。

拆成可执行的 4 件事：

1. **玩法研究**：自走棋（云顶之弈）、货币战争、卫戍协议分别借鉴什么；
2. **工程组织**：新文件夹 + 目录结构 + 架构文档；
3. **素材调研**：有没有能合法使用的「开源角色」；
4. **只搭框架**：能跑、能扩展、内容留空。

## 参考坐标（各自借鉴什么）

| 参考 | 是什么 | 我们借鉴 | 不照搬 |
|---|---|---|---|
| **《云顶之弈》** | 自走棋品类标杆 | 商店/刷新/冻结、三合一升星、利息与连胜连败、羁绊（→ 盟约）、等级（→ 调度中心） | 八人对战 PvP、海克斯/强化符文体系 |
| **崩铁「货币战争」** | 星铁的限时自走棋式玩法 | 阵营/货币组合、局内决策节奏 | 具体数值与卡池设计 |
| **《明日方舟》「卫戍协议」** | 方舟的自走棋模式：商店招募、升本、三合一、盟约、自动战斗；同时保留方舟塔防规则（部署格、朝向、攻击范围、阻挡、敌人路线与波次）；支持 1–4 人合作的「同盟模拟」与「联防」 | **主参考**：底部部署格、朝向、格挡、漏怪扣目标生命、盟约/叠层、合作玩法 | 官方具体数值、角色与关卡；也不做「复刻官方每一张图」 |

> 卫戍协议的事实依据：官方自走棋玩法，2024-11 首期，2026-11「规程」常驻；核心是自走棋运营 + 方舟塔防，
> 多人是合作而非淘汰（各自生命、可联防）。详见 [07-参考资料](07-参考资料与同类项目.md)。

## 本阶段（M0）交付 / 非目标

**交付（已完成）**

- 新目录 `arknights-autochess/`，与仓库其他实验互不干扰；
- 可运行的空壳：浏览器打开能看到 12×7 占位战场、HUD、商店/整备区/盟约面板，能推进回合；
- 数据驱动骨架：`content/` JSON + 类型 + 启动校验；改规则数值不用改代码；
- 确定性 sim 骨架：种子随机、回合状态机、经济/商店/三合一/摆放；
- 架构守卫脚本（模块边界 + `sim/` 禁用 `Math.random`/墙钟/浏览器 API）；
- 9 个测试文件、68 个用例（含真实 `content/` 校验），以及架构守卫脚本；
- 8 篇设计/调研文档 + 素材版权声明 + 未来说明。

**非目标（这一阶段明确不做）**

- 不做任何真实干员、技能、敌人、波次、正式关卡数据；
- 不做真实战斗解算（只有占位：完美防守）；
- 不做拖拽摆放、动画、特效、音效；
- 不做联机、账号、存档；
- 不做抽卡/养成/剧情/商业化。

## 成功标准（可验证）

| 标准 | 证据 |
|---|---|
| 能启动并操作 | `npm run dev` → 打开页面 → 点击「开始作战」「进入下一回合」，HUD 数字变化 |
| 工程可检查 | `npm run check` 全绿：架构守卫、`tsc --noEmit`、Vitest、`vite build` |
| 数据可扩展 | 往 `content/operators/` 放一个合法 JSON，启动后商店能抽到；放非法 JSON 启动时报错并列出问题 |
| 架构有约束 | 故意在 `src/sim/` 里写 `Math.random()` 或 import `pixi.js`，`npm run check:layers` 失败 |

## 风险（≤3）与止损

| 风险 | 说明 | 应对 / 止损 |
|---|---|---|
| **素材与 IP** | 官方角色素材没有开源许可；公开发布有下架风险 | 仓库只放自制/占位；官方素材只允许本机 `content-local/`（gitignore）；发布前跑 [05](05-美术音频与开源素材.md) 的许可清单 |
| **玩法范围膨胀** | 自走棋 + 塔防 + 联机 + 内容量大，容易做成半成品 | 先做「1 张图 + 3 干员 + 1 波敌人」的可玩闭环（M1），再谈深度；每阶段有明确验收 |
| **战斗解算复杂度** | 朝向/范围/阻挡/寻路/技能自动释放互相耦合 | M1 只做矩形/直线范围 + 接触阻挡；先用固定 tick 和简单规则，打磨放到 M2 |

止损规则：同一问题 3 次尝试无进展就停下换方案；M1 战斗原型若 2 周内跑不通，缩到「1 干员 + 1 敌人 + 1 条路」。

## 回来之后先决定的 4 件事（M1 之前）

1. **素材路线**：自制占位 / CC0 素材 / 本机官方素材（仅非商业）？
2. **战斗深度**：先做「方舟塔防」的完整规则，还是先做简化版（直线攻击 + 接触阻挡）？
3. **规模**：单人优先，还是第一版就带 1–4 人合作？（架构已预留，但工作量差很多）
4. **内容风格**：用官方干员名/数据（本地、非商业）还是原创角色（无版权风险、可公开发布）？
