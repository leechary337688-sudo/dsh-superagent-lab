## 2. 同类开源项目

| 项目 | 许可 | 技术/规模 | 可借鉴 | 不要做 |
|---|---|---|---|---|
| [sganggs/Stronghold-Protocol](https://github.com/sganggs/Stronghold-Protocol) | **GPL-3.0**（代码）；素材/数据不授权 | 浏览器 JS，Node + ws 服务端，PixiJS 7 + Preact 10；~1.9k★；数据驱动（`data/`、`schemas/`、`packs/`）、完整文档与测试 | **最重要的参考**：单包分层、`shared`/`server`/`public` 组织、数据+Schema、确定性 sim、客户端战斗 + 服务端校验、素材声明写法 | 不抄任何代码（GPL 传染，和本仓库 MIT 不兼容）；不抄素材/数据；不照搬数值 |
| [keldaanCommunity/pokemonAutoChess](https://github.com/keldaanCommunity/pokemonAutoChess) | GPL-3.0 | 浏览器自走棋，~1.8k★ | 自走棋玩法组织、地图/单位/羁绊的代码分层思路 | 同上，仅看思路 |
| [pumpkye/AutoChess](https://github.com/pumpkye/AutoChess) | MIT | 自走棋战斗模拟器（双方阵容→模拟结果） | 用模拟器验证平衡的思路；MIT 代码在保留声明的前提下可参考 | 不做成纯模拟器（我们要可玩） |
| [euphoriaer/AutoChessBH3](https://github.com/euphoriaer/AutoChessBH3) | Apache-2.0 | 崩坏3 自走棋（Unity/C#） | 数据表/羁绊结构 | 引擎不同，代码不可直接复用 |
| [OpenEmojiBattler/open-emoji-battler](https://github.com/OpenEmojiBattler/open-emoji-battler) | Apache-2.0 | 全链上自走棋 | 小而完整的自走棋循环 | 链上部分与我们无关 |
| [HelheimLabs/autochessia](https://github.com/HelheimLabs/autochessia) | AGPL-3.0 | 链上自走棋（MUD） | 仅是品类参考 | AGPL 传染性强，不碰代码 |
| [yopox/LD49](https://github.com/yopox/LD49) | **CC0-1.0** | 48 小时 game jam 自走棋 | 极简自走棋实现，CC0 理论上可复用 | 美术/完成度低，只做结构参考 |
| [customgamessourcecode/AutoChess](https://github.com/customgamessourcecode/AutoChess) | 无许可声明 | 自走棋源码 | 只能看思路 | **不能抄**（无许可 = 保留所有权利） |

> 结论：**没有可以直接 fork 的「方舟自走棋」MIT 项目**。最接近的 Stronghold-Protocol 是 GPL-3.0，
> 所以我们的策略是「独立实现 + 借鉴工程结论」，代码从零写。参考它的架构不等于复制它。

## 3. 数据与素材

完整清单、许可与替代方案见 [05-美术音频与开源素材](05-美术音频与开源素材.md)。要点：

- 官方数据表/立绘/模型/音频：版权归鹰角，社区镜像**不是开源**，只能个人非商业；
- 解包工具（Ark-Unpacker BSD-3、torappu MIT、Ark-Studio BSD-3）代码可用，资源仍版权；
- CC0/OFL 替代：Kenney、OpenGameArt、Lucide/Iconoir、思源黑体/Noto/霞鹜文楷、Freesound/Pixabay。

## 6. 调研方法与更新约定

- 新参考项目先记「许可 + 可借鉴点 + 不做什么」，再决定是否引入；
- 引入新依赖/素材时同步更新本文与 [05](05-美术音频与开源素材.md) / `NOTICE.md`；
- 星标、版本、许可会变：重要决策前重新核对（`gh api repos/<owner>/<repo>` 可看 `license`）。
