# content/ —— 数据即内容

这个目录放**游戏内容数据**（JSON），代码只负责加载、校验和解释它们。数据与代码分离是
本项目的核心约定：改平衡、加干员、加波次、画新战场，都不应该改 `src/` 里的逻辑。

> ⚠️ 当前阶段（M0）只有占位数据：`config/balance.json` 是规则参数占位，`maps/demo-board.json`
> 是战场占位。干员、技能、盟约、装备、敌人、波次都还是空目录，等设计确定后再填。

## 目录

| 路径 | 内容 | 一个文件放什么 |
|---|---|---|
| `config/balance.json` | 全局规则参数：回合数、经济、商店概率、整备区/上阵位、调度中心升级费、初始生命 | **单个文件**，整体替换 |
| `operators/*.json` | 干员定义（稀有度、职业、阻挡、攻击范围、三围、技能/盟约引用） | 一个文件一个干员 |
| `skills/*.json` | 技能定义 | 一个文件一个技能 |
| `synergies/*.json` | 盟约（对应自走棋「羁绊」）定义与激活阈值 | 一个文件一个盟约 |
| `items/*.json` | 装备/道具定义与合成配方 | 一个文件一个装备 |
| `enemies/*.json` | 敌人定义 | 一个文件一个敌人 |
| `waves/*.json` | 波次表：第几回合出哪些敌人、数量、间隔 | 一个文件一套波次 |
| `maps/*.json` | 战场：ASCII 布局 + legend 图例 | 一个文件一张地图 |

## 约定

- **稳定 ID**：`id` 一旦被别的文件引用就不要改；要改名就新增 ID 并做迁移。
- **文件名 = ID**（建议）：`operators/amiya.json` 里 `id` 也是 `amiya`，方便 review。
- **不要写注释**：JSON 不支持注释。需要解释就写在 `docs/04-数据模型与Schema.md` 或同目录
  README 里；字段含义以 `src/content/schema.ts` 的类型定义为准。
- **地图用 ASCII 布局**：`layout` 每行等宽，字符含义由 `legend` 定义，加载时转换为网格。
  改地图比改坐标数组直观，也方便 review。
- **提交前自动校验**：`npm test` 会跑 `tests/content/` 下的内容校验测试；`npm run dev` 启动时
  如果内容不合法会直接报错并列出问题。
- **版权**：从官方客户端提取的数据/素材不要直接提交到这个目录。个人研究用的本地数据放
  `content-local/`（已在 `.gitignore` 里），见 `docs/05-美术音频与开源素材.md`。
