## 三、v0.1 的诚实范围（不吹）

**只做一件事**：让手机安全地打开电脑的官方 DSH 界面（同一会话），并且**能证明它工作**。

| 有 | 没有 |
|---|---|
| 插件内 `/api/remote-url` 返回带令牌的官方界面地址 | 不做自建聊天 UI |
| 手机端一个"打开电脑界面"入口 | 不做镜像会话 |
| 安全：仅已配对设备可取地址、可吊销、记审计日志 | 不做公网中继 |
| 文档写清"为什么不用镜像/不用屏幕流" | presence/文件层留到 v0.2、v0.3 |

后续版本：v0.2 presence（设备在线 + 注入"你在哪"）、v0.3 文件（outbox + Taildrop）、v0.4 审批/提问转发（waterfall 接管 + 超时回落）。

## 四、发布流程（沿用本项目已验证的规矩）

1. 改代码只用 `write/edit`，改完 `node --check`；
2. 版本号**四处同步**：`package.json` / `src` 里的 `VERSION` / 手机端包版本 / 构建命令；
3. 本地热更新验证 → 真机验证 → 打 `.tgz`（`tar -czf <pkg>-<ver>.tgz -C dist-staging package`）；
4. `git tag v0.x.y` + GitHub Release 附 `.tgz`；
5. README 顶部写清"非官方插件、后果自担、必须用 Tailscale/私网"。

## 五、GitHub 阻塞（必须先解决）

实测：

- `git push --dry-run` → `remote: Invalid username or token. Password authentication is not supported`
- 用本机存储的凭据调 `api.github.com/user` → `401`
- 结论：**Windows 凭据管理器里那条 `git:https://github.com` 已失效**，现在既不能建仓库、也不能推送。

需要你二选一：

1. **给我一个 PAT**（推荐 fine-grained，勾 `Contents: Read and write` + `Administration: Read and write` 用于建仓；只给单个仓库则只勾 Contents），我存到本地凭据管理器，**不会打印到对话里**；
2. **你在 GitHub 网页建一个空仓库** `shi1xiao2jia3-star/dsh-remote`（不勾 README），再给我一个有 `Contents: write` 的 PAT。

拿到之后我做：本地建仓 → 提交 v0.1 骨架 + 文档 → 推送 → 开 README。

## 六、为什么这件事值得做成公开资产

- 现在的能力散在 `01-加工区/phone-bridge`，只服务这台机器；做成插件仓库后**换电脑/换手机能一键装回来**；
- 别人踩过的坑（Tailscale Serve 的 https、tarball 协议、HMR、事件形状）已经写进文档，公开出去是净收益；
- 与 `cc-remote`（MIT）形成互补：它做"Claude Code/Codex 的会话桥"，我们做"**DSH 官方界面的安全远程开放 + presence + 文件**"，不重复造轮子。
