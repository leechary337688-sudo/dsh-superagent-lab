# 三种形态与最终选择（调研收口）

2026-11-08 · 补充 `05-手机App架构方案v2.md`。两份并行调研 + B站/GitHub 对照后的结论。

---

## 一、市面上的“同一会话两端操作”，只有四种形态

| # | 形态 | 权威端（谁在跑 AI） | 实例 | 我们的处境 |
|---|---|---|---|---|
| 1 | **手机当服务端**，电脑浏览器连手机 | 手机 | **DSHA 的局域网模式**（3081 + token + `SameSite=Strict` cookie，默认关） | **零开发就有**：手机开完整 DSH，电脑浏览器打开手机地址 → 同一会话两端都能操作 |
| 2 | 电脑当服务端，手机当**可写客户端** | 电脑 | xHarness（Flutter App + Linux 连接器）、cc-remote v5.0.0、Claude Code Remote Control | 最符合“电脑的 AI 跟着我走”；手机不能离线单机干活 |
| 3 | **App 内双形态**：本地引擎 + 远程客户端 | 看会话属于哪边 | 没有现成实现（要合体） | **我们的目标**：手机上完整 DSH（单机可用）+ 连电脑时同一会话 |
| 4 | 双引擎互相转发 | 两端各一 | 现有 phone-bridge / B站 22 万播放那套 | 能“接着聊”，但两份状态会漂，不是同一会话 |

**官方写模型已钉死**：两个引擎并发同写一个会话**不可能**（内核锁 + 无合并）。所以“同一会话”必须落在 1 / 2 / 3，不能是 4。

## 二、两个关键情报（改变了推荐）

### 1. DSHA 明确拒绝“电脑当引擎、手机当 companion”

`DSH-APP/DSHA` 的 `docs/ROADMAP.md`「明确不做」里写着：**OpenClaw 架构（Gateway 跑电脑、手机当 companion node）与“手机自给自足”相反**。
它只在**反向**做多端：手机是权威端，电脑/平板用浏览器连（3081）。另外它到电脑的唯一能力是**一次性搬家**（`tools/pc-migration/dsha-portable.py`，issue #105），不是同会话。

→ 结论：**不能指望 DSHA 上游做我们的方向；要就要 fork。** 但它有两块可合法复用（MIT）：proot 运行时、移动 UI。

### 2. cc-remote 已经把“DSH 原生客户端”这条路走通了（v5.0.0，MIT）

它的 `docs/dsh-integration.md` 明确分工：**DSH 拥有模型凭据、Agent 执行、会话存储、消息准入**；cc-remote 只做设备路由、历史投影、UI。八条可抄：

1. 引擎唯一：客户端不持凭据、不执行工具，只发命令 + 订阅事件；
2. **显式“接管/释放”**，被接管方收到提示（Claude Code Remote Control 是“另一台设备接管了这个会话”）；
3. 冷历史走 `session/projections` 的 **`asOfSeq` 游标** + `session/page`，**阅读永不触发模型轮次**；
4. 事件回答绑定 **`(clientId, eventId)`**，一问只答一次；
5. 变更前落**幂等收据**（请求 hash）：重连后“已完成→不重发”“未知→先查原生状态”；
6. **不重试歧义写**；未答的提问必须由原生事件再确认；
7. 输入走**有序管道 + 队列/引导**（steer/queue），不并发发送；断连不取消 Agent；
8. 断线用“快照 + 游标”重同步，不重放字节流。

## 三、最终选择

**目标形态 = 3（App 内双形态）**，但**分两步落地**，每一步都能单独用：

| 步 | 做什么 | 为什么先做这个 |
|---|---|---|
| **M0（1 天）** | Windows 连接器：读 DSH 启动令牌 → 设备配对 → WSS 转发；**用现成 xHarness App 连我们的电脑** | 零 App 代码就能验证“电脑唯一引擎 + 手机可写客户端”在我们环境成立；同时补上 xHarness 缺的 Windows 连接器 |
| **M1（3–5 天）** | fork xHarness，接入**本地 DSH 运行时**（借 DSHA 的 proot 代码） | 达成“App 内完整 DSH”：飞行模式能单机跑 |
| M2 | 会话列表合并（本机 / 电脑）、接管提示、幂等收据（抄上面 2/4/5） | 两端操作不打架 |
| M3 | 文件：本地上传给电脑会话、电脑产物下载/预览 | 文件互通 |
| M4 | 设备感知注入（在手机/在电脑/看哪个会话） | “AI 知道我在哪” |

**现在就能体验的免费成果（不需要任何开发）**：DSHA 的「配置 → 允许局域网访问」打开后，用电脑浏览器打开它显示的地址，就是“同一会话两端操作”——只不过权威端在手机。可以先用它校准体验预期。
